# Failure analysis

The table separates observations from experiments that still need the real model. The same verified corpus, golden references, and model settings should be used for each isolated cluster fault. Restore the healthy configuration after each fault and keep the resulting JSON or logs next to its matching control run.

| Stage and isolated fault | Symptom and diagnosis | Remedy and signal |
| --- | --- | --- |
| A. Extraction, disable OCR for the image-only ORIC policy | Poppler returned zero text on all eight pages. The offline extraction test injects an empty OCR result and observes the unreadable-document error. A local control pass through Tesseract produced text on all eight pages. A second extraction defect appeared in the June 2026 handbooks. Objects from the facing page appeared between lines of clauses 1.2 and 1.10. Clipping to the PDF's visible crop removed them. | Keep OCR enabled and inspect per-source `ocr_pages` and `empty_pages`. Compare physical-page output to the rendered page before adjusting retrieval. Q08 exercises the OCR-dependent evidence. |
| B. Chunking, use fixed 100-word windows with zero overlap and discard clause boundaries | Expected cluster failure probe. A window that splits the grade table or loses the clause label can return partial evidence. The offline chunk test already exercises a long span with bounded overlap and verifies both its shared words and the persisted page/section. | Compare `recall@5` for ordinary/table and exact questions against the healthy run. Inspect the retrieved IDs against the physical pages and chunk logs. Restore section-aware windows and compare storage amplification. |
| C. Retrieval, set TOP_K to 1 or use a mismatched API model | The evaluator test moves a known evidence reference to rank four and measures recall@3 of 0.5 and recall@5 of 1.0. Its CLI test then lowers recall@5 and exits 1 without replacing the baseline. The fixture test also changes only the API model and observes HTTP 503 from `/readyz` with an embedding-pin failure. | Inspect `top_k`, chunk IDs, scores, and the readiness response. Restore k=5 and the shared model pin. Repeat the live k=1 and model-mismatch checks on the stronger laptop. |
| E. Source, allow superseded results for a current question | The fixture stack retrieves the 2023 repeat-course rule first for the explicit 2023 probe. The ordinary attendance probe checks that its retrieved list contains zero rows from the 2023 rules. Removing the current-version filter in the same fixture brings the 2023 filename into the ordinary response. The real corpus contains the eight-to-nine-week and eight-week summer rules on different pages. | Trace returned filenames, then compare the version category and the text of q09/q10. Restore the superseded filter and historical cache bypass. Record the live filter-disabled contrast after integration. |
| D. Prompt, remove the evidence boundary instruction | The deterministic model double expects a system instruction marking evidence as untrusted. The fixture test confirms the poisoned line reached the prompt and checks the returned answer contains the actual 80% rule. With the instruction removed, the double rejects both attempts and the API produces the safe fallback. This exercises request assembly, response parsing and evidence validation under controlled behavior. | Restore the system instruction and evidence delimiters. Inspect the actual answer and citations for q15 with the real model. Citation validity by itself cannot detect obedience to an injected claim that happens to cite a retrieved page. |

A partial write is a separate publication failure. In the storage tests the second Chroma batch raises and the API collection still points to its previous contents. Redis generation stays at zero. In cluster logs this should appear as a failed Job with `indexer failed`, while a lookup of the generation key still returns the previous value.
